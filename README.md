# Простые вещи — архитектура, которую можно потрогать

Публичный сайт: **https://ioc.vanya-arc.dev**. В шапке — ссылка на https://vanya-arc.dev/.

Интерактивный фильм об **инверсии зависимостей** для опытных вайбкодеров.
Сюжет: RSS → редакционный сценарий → дайджест → каналы публикации.

## Запуск

```sh
npm install
npm run dev
npm test
npm run build
```

Vite: http://localhost:4178. Нужен соседний checkout `../vanya-ui` для локального пакета Hearth & Wave.
React 19 · Motion 14 · Vite 8 · TypeScript.

## Публикация на Cloudflare

`npm run deploy` собирает статику и публикует assets-only Worker `ioc` на `ioc.vanya-arc.dev`. Конфигурация — `cloudflare.config.ts`, сборка через официальный Cloudflare Vite plugin. Артефакты находятся в `.cloudflare/output/v0/`, они исключены из git. Custom Domain управляет DNS и сертификатом; локальный dev-сервер для публичного сайта не нужен.

Для повторного деплоя нужен вход `cf auth login` или авторизованная переменная `CLOUDFLARE_API_TOKEN`. Секреты не входят в конфигурацию или репозиторий. Команда использует `--prebuilt --mode production`, чтобы публиковать уже проверенную production-сборку.

## Что можно делать

- Play/Pause, скорость 1×/1.5×/2×, предыдущая/следующая сцена, точная перемотка.
- Space переключает воспроизведение, стрелки переключают сцены вне интерактивных полей.
- На решениях фильм останавливается. Перемотка назад откатывает преобразования.
- Нажать блок схемы: объяснение и исходники контрактов/сценария.
- Сравнить **зависимости кода** и **порядок выполнения**. Движение данных показывается только во втором режиме.
- В песочнице менять источник, редактор, каналы и согласование; смотреть созданные документы.
- Светлая/тёмная темы, reduced motion, полноэкранный режим. На телефоне схема прокручивается горизонтально.

## Граница симуляции

Никаких настоящих API, публикаций или LLM-вызовов. Детерминированные адаптеры возвращают учебные материалы и записывают текстовые артефакты в локальную ленту. Это честная исполняемая модель границы, а не интеграционный тест внешних сервисов.

## DIP в самом фильме

```text
App (composition root)
 ├─ StoryPlayer → StoryDefinition ← dependencyInversionStory
 └─ DIP experiment → runDigest → MaterialSource / DraftWriter / Publisher
                                  ↑ concrete simulation adapters
```

- `src/player/contracts.ts` — контракт истории, принадлежащий плееру.
- `src/player/playback.ts` — чистые переходы воспроизведения, без React и конкретных историй.
- `src/player/` — отображение, управление, инспектор и опциональная песочница.
- `src/stories/dip/` — сцены, схемы и исполняемая модель редакции.
- `src/stories/dip/contracts.ts` — контракты задачи, без внешних форматов.
- `src/stories/dip/pipeline.ts` — правила выпуска; не импортирует адаптеры.
- `src/App.tsx` — единственное соединение конкретной истории и универсального плеера.

Чтобы добавить другой урок: создать StoryDefinition с главами, сценами, StageView и необязательным ExperimentDefinition, затем передать его в StoryPlayer. Не нужно добавлять ветки по идентификатору урока в плеер. Независимая тестовая история проверяет этот контракт. При смене story.id сессия сбрасывается.

Кофейня удалена из активной версии; предыдущая версия доступна в истории git до коммита dbc242b.

## Принцип, не каталог паттернов

Выделить файл или повторить интерфейс поставщика — ещё не DIP. Центральная сцена переносит контракт на сторону редакционного сценария и меняет направление зависимости реализации. Остальные границы повторяют тот же принцип.
