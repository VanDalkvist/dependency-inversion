# aha! — интерактивные истории, в которых можно попробовать идею

**aha!** — рабочее название серии небольших интерактивных объяснений от [VANYA / ARC](https://vanya-arc.dev/). Здесь сложную идею можно увидеть в действии, изменить что-нибудь самому и заметить результат. Не требуется знать программирование, чтобы начать; желающие могут исследовать код.

Первые две истории показывают на знакомом примере AI-помощника, почему удобно менять источники, редактора и канал публикации, не переделывая всё целиком:

- **[Как не привязать помощника к одному сервису?](https://ioc.vanya-arc.dev/)** — сюжет о независимости сценария от конкретных сервисов (DIP).
- **[Как менять инструменты у одного помощника?](https://ioc.vanya-arc.dev/di/)** — интерактивная сборка помощника из разных инструментов (DI).

**Название и оформление пока исследуются.** Предложение `aha!` находится в открытом для обсуждения [ресече ARC × aha!](docs/creative-loop/2026-11-22-arc-aha-brand-research.md). Нынешний публичный сайт может отличаться от изменений в Draft PR; работа над интерфейсом ещё не развернута. Не путайте действующий адрес `ioc.vanya-arc.dev` с предлагаемым доменом `aha.vanya-arc.dev`: последний пока не подключён.

## Запустить локально

Потребуются Node.js и два **публичных** репозитория по соседству. Сначала клонируйте [Vanya UI](https://github.com/VanDalkvist/vanya-ui), потому что приложение использует локальную зависимость `file:../vanya-ui`:

```sh
git clone https://github.com/VanDalkvist/vanya-ui.git ../vanya-ui
npm install
npm run dev
npm test
npm run build
```

Команды `npm ...` выполняются из каталога этого проекта. После `npm run dev` адрес будет напечатан Vite в терминале. React 19 · Motion · Vite · TypeScript.

Сборка Vite создаёт `dist/index.html` и `dist/di/index.html` с общими assets. Прямой переход на `/di/` обеспечен отдельным HTML-адресом.

## Публикация и лицензирование

Исходники приложения и способы локальной проверки находятся здесь. Развёртывание на Cloudflare управляется автором отдельно; публичному клону не нужны его служебные конфиги или токены. Скрипт `npm run deploy` предназначен для среды автора и может не работать в независимом клоне.

**Публичный репозиторий не равен автоматически open source.** Файл `LICENSE` пока не выбран/не добавлен; условия повторного использования кода, текста и иллюстраций необходимо определить перед публикацией. Для этого также нужна проверка истории на секреты и закрытые зависимости. См. [public-release gate](docs/creative-loop/2026-11-22-arc-aha-brand-research.md#7-public-repository-readiness-gate-partial-source-audit-no-release-approval).

## Управление и компоновка

- Play/Pause, скорость, предыдущая/следующая сцена, точная перемотка.
- Space переключает воспроизведение, стрелки переключают сцены вне интерактивных полей.
- На решениях фильм останавливается; перемотка назад откатывает преобразования.
- Блок схемы открывает объяснение и код в модальном инспекторе.
- В DIP сравниваются зависимости кода и вызовы; в DI — сборка объектов и вызовы.
- Основной урок занимает один экран. На телефоне есть панели «Схема» / «Текст»; только финальная песочница расположена ниже.
- Светлая/тёмная темы, reduced motion, fullscreen и клавиатурное управление сохранены.

## Исполняемый пример

Оба урока используют один `runDigest(brief, ports, approved)`. Он собирает материалы через `MaterialSource`, удаляет дубли, вызывает `DraftWriter` и обращается к `Publisher` только после согласования.

DI-песочница выбирает реальные учебные объекты и наблюдает их вызовы на границе сценария. Проверочный Publisher сохраняет полученный Draft и возвращает JSON-снимок. Без согласования publish не вызывается. История вызовов, документы и захваченные аргументы принадлежат отдельному запуску; результаты источника не изменяют данные следующего запуска.

Схема фильма показывает учебную сборку. Состав конкретного прогона показан ниже в его фрагменте TypeScript; наблюдатели вызовов в этом фрагменте явно опущены.

**Граница симуляции:** модели и внешние API не вызываются, сообщений и страниц во внешних сервисах не появляется. Адаптеры используют подготовленные материалы и тексты; документы собираются внутри страницы. DI не доказывает доступность или качество внешнего сервиса.

## Архитектура

```text
App / lessons (composition root)
 └─ StoryPlayer → StoryDefinition ← DIP / DI

DIP experiment ─┐
DI experiment ──┴─ runDigest → MaterialSource / DraftWriter / Publisher
                                  ↑ учебные адаптеры и recordingPublisher
```

- `src/player/` — универсальный плеер, playback, граф, инспектор, песочница; конкретных уроков не импортирует.
- `src/lessons.ts`, `src/App.tsx` — выбор страницы и передача навигации в плеер.
- `src/content-factory/contracts.ts` — контракты сценария; `pipeline.ts` — правила выпуска, без импортов адаптеров.
- `src/content-factory/adapters.ts` — общие учебные реализации.
- `src/stories/dip/`, `src/stories/di/` — собственные сцены, графы и композиция примеров.
- DI `assembly.ts` выбирает объекты; `observe-ports.ts` фиксирует вызовы и делегирует их выбранным реализациям.

Для другого урока передай `StoryDefinition` и необязательную навигацию `LessonLink[]` в `StoryPlayer`. При смене story.id сессия сбрасывается. Добавлять ветки по идентификатору урока в плеер не нужно.
