# aha! — интерактивные истории, в которых можно попробовать идею

**aha!** — серия небольших интерактивных объяснений от [VANYA / ARC](https://vanya-arc.dev/). Здесь сложную идею можно увидеть в действии, изменить что-нибудь самому и заметить результат. Не требуется знать программирование, чтобы начать; желающие могут исследовать код.

Первые две истории показывают на знакомом примере AI-помощника, почему удобно менять источники, редактора и канал публикации, не переделывая всё целиком:

- **[Как не привязать помощника к одному сервису?](https://aha.vanya-arc.dev/)** — сюжет о независимости сценария от конкретных сервисов (DIP).
- **[Как менять инструменты у одного помощника?](https://aha.vanya-arc.dev/di/)** — интерактивная сборка помощника из разных инструментов (DI).

**Айдентика:** `Vanya Arc / Aha!`, вариант №4 «С импульсом», [BRAND.md](BRAND.md). **С 23.11.2026 переработанный учебный режим уже опубликован** на [aha.vanya-arc.dev](https://aha.vanya-arc.dev/) и [/di/](https://aha.vanya-arc.dev/di/) вместе со старым алиасом `ioc.vanya-arc.dev`. Cloudflare Worker `ioc`, версия `0cb590bf-53c5-4df4-abd2-ec9be47ca576`, [цикл №2](docs/creative-loop/2026-11-23-first-view-rebuild-cycle-02.md). Релиз прошёл **100/100 тестов**, TypeScript, Vite и локальную лицензионную проверку. Человеческая проверка понимания и визуальный E2E в браузере **ещё не выполнены**. Исходники изменений остаются в **Draft PR #1**, а не в `main`.

## Запустить локально

Потребуются Node.js и два соседних публичных checkout: этот репозиторий и Vanya UI. Сначала клонируйте [Vanya UI](https://github.com/VanDalkvist/vanya-ui), потому что приложение использует локальную зависимость `file:../vanya-ui`:

```sh
git clone https://github.com/VanDalkvist/vanya-ui.git ../vanya-ui
npm install
npm run dev
npm test
npm run build
```

Команды `npm ...` выполняются из каталога этого проекта. После `npm run dev` адрес будет напечатан Vite в терминале. React 19 · Motion · Vite · TypeScript.

Сборка Vite создаёт `dist/index.html` и `dist/di/index.html` с общими assets. Прямой переход на `/di/` обеспечен отдельным HTML-адресом.

## Как устроен интерфейс сейчас

По умолчанию открыт **режим истории**, не технический плеер. Человек видит один понятный эпизод, один вопрос и крупные варианты выбора. После действия — объяснение и кнопка «Посмотреть, что дальше». Нет обязательного Play, таймлайна или технической схемы; чтение не привязано к таймеру. Понятные иллюстрации обновляются с реальными выборами и запуском.

По ссылке «Исследовать схему и код» открывается **необязательный технический режим** со старой архитектурной диаграммой, инспектором, Play/Pause, таймлайном и настройками скорости. Выборы при переходе между режимами сохраняются; прогресс истории остаётся в том же редьюсере. В финале доступна учебная песочница.

Основные тексты режима истории имеют размер **18–20px**, варианты выбора — минимум 60px по высоте. На узких экранах контент перестраивается в одну колонку. Тёмная тема и сниженная анимация предусмотрены; живой браузерный аудит мобильной композиции и 200% zoom ещё необходим.

## Исполняемый пример

Оба урока используют один `runDigest(brief, ports, approved)`. Он собирает материалы через `MaterialSource`, удаляет дубли, вызывает `DraftWriter` и обращается к `Publisher` только после согласования.

DI-песочница выбирает реальные учебные объекты и наблюдает их вызовы на границе сценария. Проверочный Publisher сохраняет полученный Draft и возвращает JSON-снимок. Без согласования publish не вызывается. История вызовов, документы и захваченные аргументы принадлежат отдельному запуску; результаты источника не изменяют данные следующего запуска.

Схема фильма показывает учебную сборку. Состав конкретного прогона показан ниже в его фрагменте TypeScript; наблюдатели вызовов в этом фрагменте явно опущены.

**Граница симуляции:** модели и внешние API не вызываются, сообщений и страниц во внешних сервисах не появляется. Адаптеры используют подготовленные материалы и тексты; документы собираются внутри страницы. DI не доказывает доступность или качество внешнего сервиса.

## Архитектура

```text
App / lessons (composition root)
 └─ StoryPlayer → guided story / expert graph → StoryDefinition ← DIP / DI

DIP experiment ─┐
DI experiment ──┴─ runDigest → MaterialSource / DraftWriter / Publisher
                                  ↑ учебные адаптеры и recordingPublisher
```

- `src/player/` — GuidedExperience (первый экран), FocusedVisual, guided-copy, а также экспертный плеер, playback, граф, инспектор, песочница; конкретных уроков движок не импортирует.
- `src/lessons.ts`, `src/App.tsx` — выбор страницы и передача навигации в плеер.
- `src/content-factory/contracts.ts` — контракты сценария; `pipeline.ts` — правила выпуска, без импортов адаптеров.
- `src/content-factory/adapters.ts` — общие учебные реализации.
- `src/stories/dip/`, `src/stories/di/` — собственные сцены, графы и композиция примеров.
- DI `assembly.ts` выбирает объекты; `observe-ports.ts` фиксирует вызовы и делегирует их выбранным реализациям.

Для другого урока передай `StoryDefinition` и необязательную навигацию `LessonLink[]` в `StoryPlayer`. При смене story.id сессия сбрасывается. Добавлять ветки по идентификатору урока в плеер не нужно.
