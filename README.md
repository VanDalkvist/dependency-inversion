## Запустить локально

Потребуются Node.js и два соседних публичных checkout: этот репозиторий и Vanya UI. Сначала клонируйте [Vanya UI](https://github.com/VanDalkvist/vanya-ui), потому что приложение использует локальную зависимость `file:../vanya-ui`:

```sh
git clone https://github.com/VanDalkvist/vanya-ui.git ../vanya-ui
npm install
npm run dev
npm test
npm run test:ui
npm run build
node ../vanya-ui/scripts/ui-pipeline.mjs inspect --project .
node ../vanya-ui/scripts/ui-pipeline.mjs check --project .
node ../vanya-ui/scripts/ui-pipeline.mjs verify --project .
```

Команды `npm ...` выполняются из каталога этого проекта. После `npm run dev` адрес будет напечатан Vite в терминале. React 19 · Motion · Vite · TypeScript.

Сборка Vite создаёт `dist/index.html`, `dist/di/index.html` и `dist/series/index.html`. Прямые переходы на `/di/` и `/series/` обеспечены отдельными HTML-адресами.

## Как устроена история сейчас

Сериал: `src/series/{model,engine,SeasonApp,season.css}` — сюжет, локальные инструменты и результат, визуальный интерфейс. Четыре сценария и отдельное ревью каждого — `docs/series/season-01/`. Старый StoryPlayer сохранён для технических фильмов.

**Главный экран — история Ани с одним текущим эпизодом.** Первый выпуск отправлен в Telegram; в обед редакции понадобился сайт. Появляется проблема, которую читатель может изменить вместе с Аней: программа должна принимать разные каналы без переделки всей подготовки новостей.

В первой истории **шесть** событий, во второй — **пять**. У каждого шага конкретное действие и последствие; кнопки продолжения называют следующее событие. Названия интерфейсов, API и исходный код доступны в отдельном режиме **«Посмотреть схему и код»**, где сохранён полный девятишаговый технический фильм. Между режимами сохраняются сделанные выборы.

Сцена с новостным листом и площадками публикации использует реальные компоненты из **`@vanya/ui`**: `CraftCard`, `Tag`, `WorkflowStrip`, `ActionButton`, `ThemeToggle`. Она показывает действие внутри **учебной, вымышленной** истории. Результаты реального учебного прогона вычисляются существующим движком; никакой внешний Telegram или сайт не вызываются.

[UI_CONTRACT.md](UI_CONTRACT.md) указывает на исходные компоненты, точный SHA Vanya UI и переносимые команды `inspect`, `check`, `verify`. `npm run test:ui` — отдельная проверка пользовательского пути в jsdom, а **не браузерный визуальный тест**. Текст основного режима — примерно 18–21 px, используется одна колонка на узких экранах, Motion учитывает reduced-motion. Фактические размеры/контраст/200% zoom в браузере и понимание непрофессиональными читателями ещё должны быть проверены отдельно.

## Исполняемый пример

Оба урока используют один `runDigest(brief, ports, approved)`. Он собирает материалы через `MaterialSource`, удаляет дубли, вызывает `DraftWriter` и обращается к `Publisher` только после согласования.

DI-песочница выбирает реальные учебные объекты и наблюдает их вызовы на границе сценария. Проверочный Publisher сохраняет полученный Draft и возвращает JSON-снимок. Без согласования publish не вызывается. История вызовов, документы и захваченные аргументы принадлежат отдельному запуску; результаты источника не изменяют данные следующего запуска.

Схема фильма показывает учебную сборку. Состав конкретного прогона показан ниже в его фрагменте TypeScript; наблюдатели вызовов в этом фрагменте явно опущены.

**Граница симуляции:** модели и внешние API не вызываются, сообщений и страниц во внешних сервисах не появляется. Адаптеры используют подготовленные материалы и тексты; документы собираются внутри страницы. DI не доказывает доступность или качество внешнего сервиса.

## Архитектура

```text
App / lessons (composition root)
 └─ StoryPlayer → guided story / expert graph → StoryDefinition ← DIP / DI

DIP experiment ─┐
DI experiment ──┴─ runDigest → MaterialSource / DraftWriter / Publisher
                                  ↑ учебные адаптеры и recordingPublisher
```

- `src/player/` — GuidedExperience (первый экран), FocusedVisual, guided-copy, а также экспертный плеер, playback, граф, инспектор, песочница; конкретных уроков движок не импортирует.
- `src/lessons.ts`, `src/App.tsx` — выбор страницы и передача навигации в плеер.
- `src/content-factory/contracts.ts` — контракты сценария; `pipeline.ts` — правила выпуска, без импортов адаптеров.
- `src/content-factory/adapters.ts` — общие учебные реализации.
- `src/stories/dip/`, `src/stories/di/` — собственные сцены, графы и композиция примеров.
- DI `assembly.ts` выбирает объекты; `observe-ports.ts` фиксирует вызовы и делегирует их выбранным реализациям.

Для другого урока передай `StoryDefinition` и необязательную навигацию `LessonLink[]` в `StoryPlayer`. При смене story.id сессия сбрасывается. Добавлять ветки по идентификатору урока в плеер не нужно.
