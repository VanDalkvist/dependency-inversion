# Viewport player Implementation Plan

**Goal:** Keep header, lesson title, current scene and transport within one viewport without downward page scrolling; only the final experiment may extend below it.
**Approved request:** User explicitly asked for a one-page main experience, excluding the late-appearing final block. Responsive layout details are implementation choices: narrow screens use Schema/Text tabs, long optional material opens in native dialogs.
**Architecture:** A bounded lesson-screen uses dynamic viewport height and flex/grid minmax sizing. Experiment remains outside it. Add a generic native Dialog; inspector and supplementary lesson content use it. Narration shows explanation or feedback, not both stacked, with an explicit switch. No changes to story, playback transitions or runDigest.

## Scope and review focus
- Preserve all narrative copy, actions, feedback, rules, source links and keyboard controls; do not hide overflow to fake acceptance.
- No body-level overflow:hidden; final experiment must genuinely remain scrollable.
- On desktop show diagram and narration together. On narrow viewports expose both through accessible buttons; each panel remains usable and controls stay in view.
- Dialogs support Escape, close and native focus return. Existing inspector region remains available inside its dialog.
- Native dialog support is missing in jsdom; test setup emulates only that browser boundary, never the player or domain behavior.
- Acceptance sizes: 1920×1080, 1440×900, 1366×768, 1280×720, 900×768, 390×844, 375×667. Below these, preserve content and accessibility rather than silently clipping it.
