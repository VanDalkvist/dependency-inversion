## 0–1. Source reality and NMT

**Trigger:** creator wants people to read, fork and learn from an educational source repo without gifting the unique film's visual identity and original storytelling or exposing a private work session.

**Functional job:** “Пусть другие переиспользуют код под MIT, но не используют мою авторскую визуальную работу как свою; я могу спокойно открыть репозиторий”.

**Emotional job:** clear sense of ownership without fake legal guarantees, and confidence that publishing will not disclose historical credentials or personal details.

**Audience:** author; public GitHub readers, contributors, educators and possible makers of derivative tools.

**Failure modes:** LICENSE suggests all files MIT while CSS/stories are restricted; reserving “all visuals” only in prose while licensing their source as MIT; overclaiming copyright on generic arcs or basic UI principles; publishing historical author email/private local evidence; assuming clean `.gitignore` equals clean Git history.

**RAT acceptance:** independent reader identifies code/story/CSS/research/brand scopes from exact file paths in under two minutes; manifest has a deterministic mapping; a full local historical secret scan plus metadata review passes before public visibility (NOT YET PERFORMED).

## 3–4. Brainstorm and adversarial critic

| Candidate | Gain | Critical problem | Outcome |
| --- | --- | --- | --- |
| One root MIT for everything | Extremely simple | Permits commercial cloning of original CSS/scene code and expression | **VETO** |
| No license at all | Reserves everything | No reusable code rights; contradicts the request | **VETO** |
| MIT + CC BY for artwork | Attribution | Commercial derivative artwork remains permitted | **VETO** |
| MIT + CC BY-NC for artwork | Stops some commercial uses | Grants noncommercial derivative/reproduction rights; doesn't match “my visual work reserved” | Hold, not chosen |
| MIT engine + protected image files only | Split of code/assets | This film's illustrations are generated by CSS and TypeScript graphs; not separate PNG assets | **VETO** |
| MIT **all** TS/TSX + generic “story strings reserved” | Maximum code reusability | Unclear contradictory licensing on mixed-content TS files | **VETO until refactor** |
| **MIT engine + reserved full CSS/creative scene modules** | Clear file-level boundary; app can be viewed, engine reused | Some TS files containing creative product logic are **not MIT**; explain tradeoff | **ACCEPT** |
| MIT code + two CC BY authored research documents | Mirrors Vanya UI's selective model | Quotes and third-party research never become CC BY by proximity | **ACCEPT limited files** |
| AGPL full source | Copyleft for server software | Does not reserve artwork and is unnecessary for this use | **VETO** |
| Proprietary whole codebase + source visible | Film exclusivity | Violates “code MIT”; unnecessary | **VETO** |

**Critic outcome:** the chosen scheme offers an honest code-vs-film boundary. Full permissive licensing of *every* film module would require moving unique narrative/diagram expressions into separate content files first. **Do not claim that every line of TS is MIT.**

## 7. Learning + next decision

**Insight:** the repo is more than MIT software: its visual film is authored in code. An accurate protected-work boundary must be file-scoped until content and rendering are physically separated. The main publication risk found is **personal Git author metadata**, not a leaked API token. The next decision is about history/privacy, not about selecting a better license.
